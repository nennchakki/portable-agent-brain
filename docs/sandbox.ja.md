# コンテナや隔離された実行環境で使う

[English](sandbox.md) | 日本語 | [説明書一覧](README.ja.md)

ホストとAIは、同じ環境とは限りません。AIが同じパソコンで動いていても、自分とは別のホームフォルダを使っていたり、見えるフォルダが制限されていたり、読み取り専用で動いていたりすることがあります。見える場所を基準に、保存先を指定してください。

## AIから見えるパスを使う

```sh
export BRAIN_LIBRARY="/brain"
brain context --project sample-weather-cli "inspect cache behavior"
```

環境変数を使わず、コマンドごとに指定することもできます。

```sh
brain context --library /mnt/agent-library \
  --project sample-weather-cli \
  "inspect cache behavior"
```

明示した `--library` は、環境変数や保存済みの初期値より優先されます。ホスト側の `$HOME` とAI側の `$HOME` が同じ場所だとは限りません。

## 読み取り専用でメモを渡す

検索だけなら、書き込み権限はいりません。保存先を読み取り専用でmountできます。

```text
ホスト                            AIの実行環境
private agent-library  --read-only-->  /brain
```

Dockerの例は次のとおりです。

```sh
docker run --rm \
  --mount type=bind,src="${BRAIN_LIBRARY}",dst=/brain,readonly \
  -e BRAIN_LIBRARY=/brain \
  <agent-image>
```

`${BRAIN_LIBRARY}` はホストのshellで展開されます。コンテナ内のAIから見える保存先は `/brain` です。この状態では `search` と `context` を使えます。メモの保存は、安全に失敗します。

## シンボリックリンクが見えない場合

ホスト側では使えるシンボリックリンクでも、AIの環境にリンク先がmountされていなければ開けません。できるだけ、実際の保存フォルダを直接mountしてください。

シンボリックリンクを使う必要がある場合は、リンクとリンク先の両方がAIから見えることを確認します。新しいメモの入力ファイルや保存先には、シンボリックリンクを使わないでください。保存先が不明確だったり別の場所へ向け直されたりした場合は、安全に失敗させます。

## 確認済みメモは読み取り専用、確認待ちだけ書き込み可能にする場合

より細かく分ける場合は、確認済みのメモ全体を読み取り専用にし、確認待ちのメモを置く場所だけ書き込み可能にします。

```text
/brain                         読み取り専用
└── inbox/
    └── candidates/            書き込み可能な別mount
```

Dockerでの構成例です。

```sh
docker run --rm \
  --mount type=bind,src="${BRAIN_LIBRARY}",dst=/brain,readonly \
  --mount type=bind,src="${BRAIN_CANDIDATES_HOST}",dst=/brain/inbox/candidates \
  -e BRAIN_LIBRARY=/brain \
  <agent-image>
```

`BRAIN_CANDIDATES_HOST` は、ホスト側で場所を示すための例です。Portable Agent Brainが読む設定名ではありません。

これは安全な構成を検討するための形です。現在のCLIには、確認待ちフォルダだけを別パスにする設定はありません。保存するには、メモ保存先の中に書き込み可能な `inbox/candidates/` が必要です。使っているコンテナ機能が、読み取り専用mountの内側に別の書き込み可能mountを安全に作れることを確認してから、自動保存を有効にしてください。検索だけなら、この追加設定は不要です。

## 権限を最小限にする

- `context` に必要なメモだけ読めるようにする。
- 確認待ちのメモは、ほかの利用者から読めない場所にする。
- 認証情報のフォルダやホームフォルダ全体をmountしない。
- lockや一時ファイルも、同じように保護されたファイルシステムへ置く。
- 誰でも書き込めるパス、安全だと確認できないパス、別の場所へ向け直されたパスを、新しいメモの保存先として拒否する。

書き込み権限を広げることは、接続エラーの一般的な解決方法ではありません。どのパスに、どの操作が必要かを先に確認してください。

## AIの指示書も、その環境から読めるようにする

setupは、設定ファイルを実際に使う環境で行い、その環境から共通指示書を読めることを確認します。ホストの絶対パスをAIの設定へ書いても、コンテナ内に同じパスがなければ動きません。

ソフト本体をmountできない環境では、確認した短い共通指示書だけを、変わらない場所へコピーする方法もあります。その場合も、自分のメモまでAIの共通設定へコピーしてはいけません。コピーを更新する方法と、参照先が正しいことを確認してください。

## 接続後に確認すること

1. `BRAIN_LIBRARY` または `--library` が、AIから見えるmount先を指している。
2. `search` と `context` が、保存先の外へ出ずに動く。
3. 壊れたwikilinkや保存先外へのwikilinkを拒否する。
4. 読み取り専用の利用では、cacheやtelemetryを書き込まない。
5. 保存を許可した構成では、確認待ちフォルダだけに書く。許可していなければ安全に失敗する。
6. 接続時にメモ全体をAIへ読み込ませない。

AI側で見える場所と、ホスト側で見える場所の両方を記録すると、パスの取り違えを見つけやすくなります。
