# プライバシーと公開前の確認

[English](privacy.md) | 日本語 | [説明書一覧](README.ja.md)

Portable Agent Brainは、初期状態ではメモを手元に保存します。新しい保存先は空で、ソフト本体に外部サービスは不要です。Gitは必須ではありません。

ただし、手元に保存した文章が、接続したAIから外部へ送られないとは限りません。クラウド型AIが選ばれたメモを読むと、そのAIの提供会社が、自社の利用条件やアカウント設定に従って文章を処理する場合があります。作業に必要な部分だけを選び、そのサービスのデータ設定も確認してください。

## 公開ソフトと自分のデータを分ける

公開リポジトリに入れてよいものは次のとおりです。

- CLIと検査のコード。
- 書式定義と、空の書式見本。
- AIを接続するための短い指示書。
- 説明書。
- 説明・テスト用で、完全に架空だと明示した見本。

次のものは入れてはいけません。

- 利用者の実際のプロジェクト、失敗から得たメモ、判断、好み、確認待ちメモ。
- 会話、セッション履歴、作業記録、移行レポート。
- 実行時の記録、cache、backup、パソコンごとの状態。
- 非公開リポジトリのアドレスや、非公開のシステム構成。
- 個人の絶対パス、身元がわかるデータ、メールアドレス。
- 認証情報、環境設定ファイル、証明書。

公開版は、確認した一般的なソースだけを独立した公開リポジトリへ入れて作ります。非公開のメモ保存先を、情報を伏せただけのcloneとして公開してはいけません。そのGit履歴も取り込みません。

## 手元での保存

自分のメモは、個人情報に合ったアクセス権を設定した別のフォルダに保存します。公開ソフトと自分のメモは、別のGitリポジトリにしてください。

書式見本や `.gitignore` は、誤って追加する可能性を下げるだけで、安全を保証する境界ではありません。commit前には、追加予定のファイルとリポジトリの状態を確認します。

## 任意のGit接続先

1台のパソコンだけでも使えます。バックアップや複数端末での利用が必要なら、自分のメモだけのGitリポジトリを作り、自分で管理する非公開の接続先を使ってください。

[GitHubへの保存機能](github-sync.ja.md)はprivate・書き込み権限・リポジトリID・送信する履歴を検証します。publicや確認不能な接続先は拒否し、公開範囲を勝手に変更しません。直接のGit操作や、後からGitHubでpublicへ変える操作まで制御するものではありません。

最初にpushする前に、次を確認します。

1. 接続先が非公開である。
2. 接続先のURLと、送信予定のファイル一覧が正しい。
3. 現在のファイルとGit履歴に秘密情報がないか検査した。
4. cache、確認待ちメモの書き出し、backup、環境設定ファイルが除外されている。
5. 保存サービスのデータ保持方針と、共同利用者の範囲を理解している。

いったん公開した接続先を非公開に変えても、それまでの公開をなかったことにはできません。

## メモを保存するときのプライバシー

保存コマンドへ渡すのは、短いJSONの作業要約です。会話の原文ではありません。新しくわかったこと、利用者からの訂正、確認できた失敗と成功の方法、次にも役立つ具体的な内容だけを残します。

認証情報、authorizationの値、秘密鍵、生のセッションID、telemetry記録のような入力は拒否します。どの種類の問題かは知らせますが、検出した値自体を表示してはいけません。

確認待ちでも、秘密は秘密です。検索での優先度が低くても、確認済みメモと同じように、利用者の非公開データとして扱ってください。

## 過去の会話を自動で取り込む機能はない

バージョン0.1では、`--history-source` は手元の履歴を見直す手順を表示するだけです。明示されたパスが存在することは確認しますが、中身を開く、解析する、コピーする、取り込む、といった処理はしません。

将来この機能を作る場合も、利用者の明示的な許可を必要とし、会話をコピーするのではなく、短い確認待ちメモを保存する仕組みにします。

履歴の書き出し、未加工のチャット、移行レポート、履歴処理に使ったファイルは、公開ソフトにも、通常のメモ保存先にも入れないでください。

## 公開前の安全確認

公開版をcommitする前に、`brain release-check` または同等の検査を実行します。次が見つかった場合は失敗させます。

- 外部のdenylistで明示した、個人プロジェクトや身元を示す文字列。
- 個人の絶対パスや、非公開の接続先。
- 利用者の確認待ちメモを含むフォルダ。
- 実行時の記録、cache、backup、パソコンごとの設定。
- 認証情報らしい値やファイル。
- 壊れた書式見本、書式定義、説明書のリンク。
- 公開版を非公開の元データへ結びつけるGitの接続先や履歴。

検査は、Gitで管理しているファイルと、まだ追加していない配布対象のファイルを調べます。初回公開前には、すべてのcommitと、そこから参照できるGit objectも確認します。公開に必要な所有者名やリポジトリ名だけを、範囲を限定して例外登録し、その例外を結果に表示します。

scanner本体やテストの見本に、実際の個人名を入れないでください。文字を分割したりencodeしたりした値も同じです。自分用の非公開文字列は、公開ソフトの外にあるJSON配列として保存し、パスを明示します。

```sh
brain release-check --denylist /private/release-markers.json
```

このファイルは手元で読み、配布物へコピーしません。検出した文字列も表示しません。`--denylist` を省略しても、秘密情報、非公開パス、確認待ちメモ、実行時データ、接続先、Git履歴は検査します。ただし、自分の組織だけで使う文字列の検査は行われません。JSONの結果には、外部の文字列検査を行ったかが記録されます。文字列のパターン検査だけでは、すべての個人情報を判断できません。

自動検査には、問題のないものを検出する場合と、文章の意味に埋もれた漏えいを見つけられない場合があります。最後は、人の目でも確認してください。対象は見本、コメント、テスト、Git履歴です。実在するプロジェクトの名前を変えただけでは、公開用の架空データになりません。

`brain release-check` は現在のフォルダ、または `--root` で指定した場所を調べます。シンボリックリンク、確認していないbinary、1MBの上限を超えるtextを、黙って省略せず拒否します。READMEの画像だけは、パス、SHA-256、画像形式、metadataを確認したうえで明示的な例外にしています。検査結果にも例外として表示しますが、画像の中身を自動で個人情報検査するものではありません。画像が変わったら、もう一度人が確認します。

この機能が調べるのはソースリポジトリです。配布用archiveは、含まれるファイルとmetadataを別に確認する必要があります。

`uv build` は、小さなbuild backendのwrapperを使い、source archiveのUID/GID、所有者名、時刻、拡張metadataを一定にします。buildした人のアカウント情報がtarのheaderへ入ることを防ぐためです。Setuptoolsのlicenseを変えたり、実行時のdependencyを増やしたりはしません。

## 秘密情報が見つかった場合

1. 公開作業を止め、値をissueなどへ貼らない。
2. 提供元で認証情報を無効化または変更する。
3. 現在のファイルと、参照可能なGit履歴から削除する。
4. clean cloneから検査をやり直す。
5. log、配布物、mirrorに別のコピーがないか確認する。

削除だけでは足りません。Git履歴に入った後は、現在のファイルから消しても、古い履歴に値が残っています。

## 実行記録と、原本から作る別の表示

公開版には、利用者の実行記録を入れません。将来、任意で手元だけに回数などを記録する場合も、メモのグラフ外に置き、作業本文やIDを入れず、自動でメモを承認したり作業上の決まりを変更したりする目的には使いません。

Markdownが原本です。HTML、索引、cache、グラフ表示は原本から作り直せるデータとして扱い、意図的に確認した公開説明でない限りcommitしません。
