# コマンド中心の導入手順

[English](getting-started.md) | 日本語 | [説明書一覧](README.ja.md)

この手順では、自分のメモを保存するフォルダを作り、AIにつなぎます。外部のサーバーは不要です。

ターミナルやGitに慣れていない方は、先に[初めての設定と使い方](guide.ja.md)を読んでください。コマンドの一覧、現在の制限、Hermes-Agentとの違いは[機能・コマンドの解説](features.ja.md)にあります。

## 1. ソフト本体をダウンロードする

```sh
git clone https://github.com/nennchakki/portable-agent-brain.git
cd portable-agent-brain
```

このフォルダは公開ソフトの置き場です。自分のメモは別のフォルダに保存し、通常は非公開にしておきます。

このコマンドは `main` の内容を取得します。設定と、許可した過去のチャットからのメモ作りをAIに任せる場合は、[セットアップ用プロンプト](../prompts/setup-and-import.ja.md)を使ってください。

## 2. 対話形式で初期設定する

```sh
./brain setup
```

順に、次の内容を設定・確認します。

1. メモの保存先。初期値を使うか、自分で指定します。
2. 接続するAI。
3. `brain` コマンドを配置するかどうか。
4. AIにメモの使い方を伝える、短い指示の追加。
5. 手元だけで使うか、Gitの接続先も設定するか。
6. 必要に応じて、過去の会話を見直す手順の表示。setup自体は履歴を読みません。
7. 設定結果と変更したファイルの確認。

表示されたパスを確認してください。引数で指定する場合は `--claude-file`、`--codex-file`、`--generic-agents-file` を使います。既存の設定ファイルを変更するときは、関係のない文章を残し、バックアップを作り、追加部分に目印を付けます。再実行しても同じ設定を重ねて追加しません。

書き込み前に検出できる競合は先に確認します。途中で失敗した場合、setup自身が行った設定・指示書の接続・コマンドの変更を戻します。Gitの設定は最後です。Gitが途中で失敗した場合は `.git` の状態を残し、手動確認が必要なことを知らせます。変更履歴を削除して元に戻ったように見せる処理はしません。停電やプロセスの強制終了では、この復元処理が動かない場合があります。

## 3. 対話形式を使わず、保存先だけ作る

AIへの接続やGitの設定をせず、保存先だけ作る場合は次のようにします。

```sh
export BRAIN_LIBRARY="${HOME}/agent-library"
./brain init --library "$BRAIN_LIBRARY"
```

コンテナなどの隔離された環境では、その環境の中から実際に見えるパスを使ってください。

```sh
export BRAIN_LIBRARY="/brain"
./brain init --library "$BRAIN_LIBRARY"
```

保存先は、次の順で決まります。

1. コマンドの `--library`。
2. 環境変数 `BRAIN_LIBRARY`。
3. setupで保存した設定。
4. 初期値の `~/agent-library`。setupでは作成前に場所を表示します。

AIのホームフォルダが自分のものと違う場合、`~` が同じ場所を指すとは限りません。シンボリックリンクも、リンク先がAIから見えなければ使えません。

## 4. 最初は空であることを確認する

新しい保存先には空のフォルダだけがあり、自分のメモもサンプルも入っていません。書式見本は、実際のメモと混同しないようソフト本体のフォルダに残します。初期状態の件数は次のとおりです。

```text
Projects: 0
Lessons: 0
Decisions: 0
Preferences: 0
Procedures: 0
Candidates: 0
```

あとで `TEMPLATE.md`、`.gitkeep`、書式見本のREADMEをコピーした場合も、検査では説明用ファイルとして扱い、メモの件数には含めません。

## 5. プロジェクトを登録する

`templates/project/` のファイルを、自分の保存先に作ったプロジェクト用フォルダへコピーします。`replace-me` をすべて置き換え、各項目を確認してから検索に使ってください。

```text
projects/<slug>/
  <slug>.md
  project.yaml
```

`slug` はプロジェクトの短い識別名です。Markdownファイルはそのプロジェクトの概要メモ、`project.yaml` は検索の設定です。設定には概要メモの場所や、作業の種類に応じて確認するメモを指定します。

一式の見本は[架空のsample-weather-cli](../examples/demo-project/README.ja.md)にあります。説明とテスト用のデータで、新しい保存先へ自動で入るものではありません。

## 6. 作業に関係するメモを探す

候補をキーワードで探すには、`search` を使います。

```sh
./brain search --library "$BRAIN_LIBRARY" "cache expiry"
```

特定のプロジェクトの作業に必要なメモを読むには、`context` を使います。

```sh
./brain context --library "$BRAIN_LIBRARY" \
  --project sample-weather-cli \
  "debug stale cached output"
```

`context` はプロジェクトの設定と作業の種類に合わせてメモを選び、関連するリンクをたどり、重複を除いて、出力量を制限します。保存先の全内容をAIへ渡すわけではありません。

明らかな1文字の誤字修正や単純な名前の変更など、過去の知識が結果に影響しない作業では検索を省きます。

## 7. 次にも役立つことを保存する

作業を終えて結果を検証したら、会話の原文ではなく、必要な項目に分けた短い要約を渡します。

```sh
./brain learn-extract --library "$BRAIN_LIBRARY" \
  --project sample-weather-cli \
  --task-type debugging \
  --stdin < examples/demo-project/task-summary.json
```

これは架空の入力を使う例です。実際には、登録したプロジェクトと自分の作業の要約に置き換えてください。

保存する内容がなければ、0件で終わることもあります。保存する場合は `inbox/candidates/` に確認待ちのメモを作り、既存の確認済みメモは変更しません。詳しくは[作業後のメモの保存](automatic-capture.ja.md)を参照してください。

## 8. AIを接続する

setupを再実行して接続するAIを選ぶか、[AIごとの接続方法](agent-integration.ja.md)に従ってください。各AIは、アダプターと呼ぶ同じ短い指示書を参照します。自分のメモをAIの共通設定にコピーする仕組みではありません。

専用の接続手順がないAIには、[接続用プロンプト](../prompts/connect-agent.ja.md)を使えます。

## 9. Gitを使うか決める

Gitは必須ではありません。次のどの使い方でもかまいません。

- Gitを使わず、1台のパソコンに保存する。
- 手元だけのGitリポジトリで変更履歴を残す。
- バックアップや複数端末での利用のために、非公開のリモートを使う。
- 自分で管理している既存の非公開リモートを使う。

実際のメモを公開ソフトのリポジトリに入れないでください。[private GitHubへの接続と送信](github-sync.ja.md)では、登録と送信の前にprivateと書き込み権限を検証します。送りたい履歴全体をプレビューで確認してから送信してください。

## 10. 公開ソフトを変更したら検査する

配布するソフト側を変更したときは、次を実行します。

```sh
./brain release-check
```

これは、非公開情報の混入を見つけるための補助です。Gitの履歴を自分で確認することや、漏れた認証情報を無効にすることの代わりにはなりません。[プライバシーと公開前の確認](privacy.ja.md)も参照してください。

## 更新するとき

ソフト本体と自分のメモは別々に更新します。ソフト側の手元の変更を保護し、新しい版の内容を確認してから更新してください。メモの書式を変える前には、メモをバックアップするかGitに記録し、検査を実行します。
