# はじめて使う人のための詳しい使い方

[English](guide.md) | 日本語 | [READMEに戻る](../README.ja.md)

Portable Agent Brainは、AIとの作業でわかったことを、自分のパソコンにメモとして残す道具です。使うAIを替えても、そのメモを次のAIに読んでもらえます。

プログラミングの知識は前提にしていません。「コマンドを実行」と言われても困る人は、最初から順に読んでください。設定をAIに任せるなら、まず1〜3章を読み、設定後に6〜8章へ進めば大丈夫です。困ったときだけ読む説明と用語集は後半にあります。

## 1. 引き継ぐのは、次の作業に役立つメモ

たとえば、あるAIと作業して「このプロジェクトでは日付を年・月・日の順で書く」「この方法は失敗したので、次は別の手順を使う」とわかったとします。次のAIに同じ説明を繰り返す代わりに、必要なメモを読んでもらうための仕組みです。

会話全体やAIの内部状態を移すものではありません。次のAIが前のAIとまったく同じ受け答えになるわけでもありません。残すのは、好み、作業上の決まり、確認できた事実、失敗から学んだことなどです。

保存には、人が読める普通のテキストファイルを使います。見出しやリンクを書ける形式をMarkdownといい、ファイル名の末尾は `.md` です。あとで別のソフトを使いたくなっても、メモはファイルとして手元に残ります。

### ソフト本体と、自分のメモは別の場所に置く

この説明では、次のように分けます。`~` は、パソコンの「自分用のホームフォルダ」を表す記号です。

| 場所 | 入っているもの | 気をつけること |
|---|---|---|
| `~/portable-agent-brain` | 公開されているソフト本体と説明書 | 自分の会話履歴やメモを入れない |
| `~/agent-library` | 自分のメモ | 大切なデータとして保管する。公開しない |
| 各AIの設定ファイル | メモの使い方を知らせる短い参照 | 既存の設定を消さずに追加する |

「リポジトリ」は、Gitという道具で変更履歴を管理するファイルの集まりです。ここでは、GitHubに置かれた公開ソフトのことだと思って読み進めてかまいません。公開ソフトをダウンロードしても、自分のメモがGitHubへ送られるわけではありません。

## 2. 必要なものと、最初に知っておきたいこと

現在の対応環境はmacOSとLinuxです。ソフトを動かすPython 3.11以上と、ここで紹介するダウンロード方法ではGitを使います。Windows単体での動作は、この版の対応範囲に入っていません。Windowsの方は、このページのコマンドをそのままPowerShellに貼らず、使っているAIに対応環境を確認してください。

普段使うAIは別途必要です。パソコン内のファイルを読めて、コマンドを実行できるAIなら、設定やメモ作りを任せられます。チャット画面があるだけでは、それらの操作ができるとは限りません。

Obsidianは、メモを読み、メモ同士のつながりを図で見るためのアプリです。なくてもPortable Agent Brainは使えます。見やすく読みたいときに追加してください。

Portable Agent Brain本体のために、サーバーや専用のAPIキーを用意する必要はありません。ただし、使うAIサービスの契約や利用料は別です。履歴を大量に読ませれば、そのAIの利用量も増えます。

**手元に保存することと、外部へ一切送らないことは別です。** クラウド型のAIがメモを読むと、その内容がAIサービス側で処理される場合があります。会社や他人の情報を使うときは、その情報をAIに渡してよいか先に確認してください。詳しくは[プライバシーの説明](privacy.md)を参照してください。

## 3. AIに任せるなら、この文章を渡す

[セットアップ用プロンプト](../prompts/setup-and-import.ja.md)を開き、冒頭の灰色の枠内の文章を、使いたいAIのチャットへコピーしてください。これはターミナルではなく、AIに送る文章です。

さらに、次の一言を添えてもかまいません。

```text
パソコンの設定には慣れていません。
変えるファイルと保存先を先に教えて、私が操作するところは一つずつ案内してください。
履歴は、私が許可した範囲だけ使ってください。外部への同期は使いません。
```

AIは、今の環境で読まれる設定ファイルを調べ、共通の指示書への参照を追加します。その後、利用してよい履歴を確認して、最初のメモを作ります。もともとの設定や、保存済みのメモを消す手順ではありません。

聞かれるのは、主に「どこに保存するか」「どのAIにつなぐか」「どの履歴を使ってよいか」です。最初は1つのAI、1つのプロジェクト、最近の短い履歴からで十分です。履歴が読めないAIには、必要な部分を書き出したファイルを渡す方法があります。ほかのチャットを自動で全部読めるとは考えないでください。

AIが設定ファイルを変更できない場合は、利用者が貼る設定文を作ってもらいます。「できない」と言われた操作まで、完了したことにはなりません。どこまでできたかを確認して、必要なら次の章の操作を行ってください。

## 4. 自分で始める場合は、ターミナルで1行ずつ実行する

ここからは、まだこのソフトをダウンロードしていない人向けの手順です。すでにAIが設定を済ませた場合は、同じ場所にもう一度ダウンロードせず、6章へ進んでください。

### ターミナルを開く

Macでは、Finderの「アプリケーション」から「ユーティリティ」を開き、「ターミナル」を起動します。これは、文字でパソコンに操作を伝えるアプリです。[Appleの操作説明](https://support.apple.com/en-lamr/guide/terminal/apd5265185d-f365-44cb-8b09-71a064a42125/mac)

Linuxでは、アプリ一覧から「端末」または「Terminal」を開きます。名前や開き方は使っているLinuxによって異なります。

この先の灰色の枠にあるコマンドを1行コピーし、ターミナルへ貼り付けてEnterを押してください。Macでの貼り付けはCommand＋Vです。画面にもともとある `%` や `$` は入力しません。説明文や、枠を作るための記号も貼り付けないでください。

実行後にまた入力できる行が出たら、次へ進みます。エラーが出たときは、そのまま残りを実行せず、11章を見てください。

### GitとPythonを確認する

まず、次を実行します。

```sh
git --version
```

`git version` に続いて番号が出れば、Gitが見つかっています。見つからない場合は[Git公式のMac向け案内](https://git-scm.com/install/mac)を確認してください。Linuxでは、使っているLinuxに合った導入方法を調べます。

次にPythonを確認します。

```sh
python3 --version
```

`Python 3.11`、`Python 3.12`など、3.11以上なら進めます。見つからない、または古い場合、Macでは[Python公式のダウンロードページ](https://www.python.org/downloads/macos/)から対応するインストーラーを入れてください。インストール後はターミナルを開き直し、同じコマンドで確認します。Linuxでは、OSの種類とバージョンをAIに伝えて導入方法を確認してください。

Pythonでプログラムを書ける必要はありません。このソフトを動かすために使います。理由のわからないインストールコマンドを次々に試す必要もありません。

### ソフトをダウンロードする

次の4行を、上から1行ずつ実行します。

```sh
cd ~
git clone --branch feat/initial-public-release https://github.com/nennchakki/portable-agent-brain.git
cd portable-agent-brain
./brain setup
```

最初の `cd ~` はホームフォルダへ移動する操作です。`git clone` でソフトをダウンロードし、次の `cd` でそのフォルダへ移動します。最後の行が初期設定を始めるコマンドです。`./` は「今いるフォルダの中の」という意味です。

公開準備中のため、ここでは実装の入っている `feat/initial-public-release` というブランチを指定しています。ブランチは、開発途中の変更を分けて置く場所です。`main` に実装がない状態で、ブランチ指定を消さないでください。

`already exists` と出た場合、その場所にはすでにフォルダがあります。消してやり直す前に、AIに既存のフォルダを確認してもらってください。

## 5. 初期設定では、保存先と使うAIを選ぶ

設定中の質問は英語で表示されます。`[]` の中は、何も入力せずEnterを押したときに使う値です。

| 表示される質問 | 入力するもの |
|---|---|
| `Notes folder` | メモの保存先。初回は通常 `~/agent-library` に当たる場所。表示された場所を確認する |
| `Agents (comma separated: claude,codex; blank for none)` | Claude Codeなら `claude`、Codexなら `codex`、両方なら `claude,codex`。空欄なら接続しない |
| `Install brain command? (y/N)` | 迷うなら `N`。このページではソフト内の `./brain` を使う |
| `Git mode (none/local/existing/remote)` | 最初は `none`。メモのGit管理や外部同期を追加しない |

すでに設定があると、保存先などの初期値が違う場合があります。保存先は、ソフト本体のフォルダとは分けてください。iCloud Driveなど、すでに自動同期する場所を選ぶ場合は、そこへ保存すると何が送られるかも確認します。

`none` は、新しくGit管理や同期を設定しないという意味です。保存先にもともとあるGit設定や、ほかのアプリの同期機能を無効にする選択ではありません。

`claude` はClaude Codeのことです。似た名前のチャットサービスまで、この指定で接続できるという意味ではありません。他のAIは、3章のプロンプトから接続方法を調べてもらってください。単に `generic` と入力するだけでは、接続先の設定ファイルを特定できません。

### 設定ファイルには、短い参照だけが追加される

共通の入口は、ソフト内の `adapters/external-brain.md` です。そこに「必要なときだけメモを探す」「役立つ結果を確認待ちのメモとして保存する」といった使い方が書かれています。ここでいう接続は、この指示書をAIに読んでもらうことです。通信を中継するサーバーではありません。

初期設定は、対象の設定ファイルにこの指示書への参照を追加します。既存の文章を残し、変更前のバックアップを用意します。どのファイルを変えたかは結果で確認してください。

Codexでは、通常の `AGENTS.md` より `AGENTS.override.md` が優先される場合があります。そのため、ファイルに追記できただけで有効とは限りません。AIに読み込み先を確認してもらい、設定後は新しいセッションで試してください。[Codexの設定ファイルの説明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

`Install brain command?` で `N` を選んだ場合は、接続するAIにソフト内の `brain` の場所も伝えてください。この手順どおりなら `~/portable-agent-brain/brain` です。別の作業フォルダからは `./brain` が見つからないため、AIから見える絶対パスで呼び出せるか確認します。`y` を選んでも、検索対象のフォルダにコマンドが入っていなければ、どこからでも呼べるとは限りません。

## 6. 設定が済んだら、空の状態を確認する

初回の保存先は空です。サンプルの知識や作者の会話履歴が入るわけではありません。ここまでで「入れ物」と「AIからの接続」を用意しました。

設定に使ったターミナルで、次を実行します。

```sh
./brain validate --library "$HOME/agent-library"
```

`$HOME` もホームフォルダを表します。このコマンド中の `$HOME` は、`$` ごとコピーしてください。画面の入力待ち表示の `$` とは別です。保存先を変更した人は、`"$HOME/agent-library"` の部分を自分の保存先へ置き換えてください。空白を含む場所でも1つの指定として扱えるよう、引用符 `"` は付けたままにします。

これは、メモの形式やプロジェクトのリンクに問題がないか調べるコマンドです。エラーが0件であることを確認してください。ノード数が0でも、初回なら正常です。検査が通っても、メモの内容が事実だと保証されるわけではありません。

プロジェクト別のメモを作るには、先にそのプロジェクトを登録します。初心者の方は、AIに次のように頼んでください。

```text
これから取り組むプロジェクトをPortable Agent Brainに登録してください。
名前、短い識別名、概要、現在の資料の場所を私に確認してから作ってください。
すでに登録されている場合は作り直さず、登録後に形式を検証してください。
```

短い識別名を `slug` と呼びます。AIは確認した内容を使って、プロジェクトの概要メモと `project.yaml` という設定ファイルを作ります。最初から自分でYAMLやJSONという書式を書く必要はありません。

## 7. 最初のメモは、許可した履歴から作る

すでに過去の作業があるなら、3章のプロンプトを使い、「このプロジェクトの、今月の履歴だけ」など範囲を指定してください。AIが読めない履歴は、サービスの書き出し機能などで必要な部分だけ用意します。パソコンの中身や全チャットを丸ごと渡す必要はありません。

`--history-source` という名前のオプションはありますが、現時点では手順を表示するだけです。履歴を読むのはプロンプトを渡されたAIで、内容を短くまとめてから保存コマンドへ渡します。「計画が出た」だけでは、メモはまだできていません。

たとえば、こう依頼できます。

```text
このプロジェクトで次にも役立ちそうな好み、注意点、失敗の原因を短いメモにしてください。
古い話と今も確認できる事実を分けて、確認待ちとして保存してください。
パスワードや会話の原文は保存せず、何件保存したかと保存先を教えてください。
```

新しいメモは、保存フォルダ内の `inbox/candidates/` に入ります。英語の `pending` や `candidate` は、ここでは「人が確認する前のメモ」という意味です。保存したからといって、今後の作業で必ず従う決まりになるわけではありません。参考として検索できますが、現在の資料や確認済みの指示を優先します。

メモを読んだだけで、確認済みへ切り替わるわけではありません。最初は確認待ちのまま使えます。正式な指示として採用したい場合は、根拠と変更箇所を確認してから行ってください。詳しい書式は[メモの保存方法](automatic-capture.md)にあります。

役立つ情報がなければ、保存が0件でもかまいません。多く作ることより、あとで読んだときに役立つことを優先します。

## 8. Obsidianでは、メモの保存フォルダを開く

メモができたら、[Obsidian](https://obsidian.md/)で読めます。まだ入れていない人は、公式サイトのDownloadから自分のOS向けのアプリをダウンロードして、インストールしてください。開くのはソフト本体の `portable-agent-brain` ではなく、自分のメモがある `agent-library` の方です。

1. Obsidianを開き、保管庫の管理画面を開きます。すでに別の保管庫を使っている場合は、左下の保管庫名のメニューから管理画面へ進みます。
2. `Open folder as vault`（フォルダを保管庫として開く）を選びます。
3. 自分のメモの保存フォルダを選びます。
4. 左側にメモが表示されたら、1件開いて内容を読みます。
5. 左側のグラフ表示アイコンから、メモ同士のつながりを見ます。

Obsidianでは、ひとまとまりのメモのフォルダを「保管庫」またはvaultと呼びます。画面の言葉や配置はバージョンで変わることがあります。[保管庫を開く手順](https://obsidian.md/help/manage-vaults)と[グラフ表示の説明](https://obsidian.md/help/plugins/graph)も参照してください。

![Obsidianで既存のメモのつながりを表示した例](images/obsidian-graph.png)

これは、すでにメモがある状態の例です。導入直後から同じ図が出るわけではありません。

点がメモ、線がメモ同士のリンクです。線が多いほど正しい、という意味ではありません。リンクがないメモは離れて表示されることがあります。内容に関係があるメモをAIにつないでもらってください。図を埋めるために、無関係なメモを結ぶ必要はありません。

確認待ちのメモもObsidianでは表示できます。一方、`brain validate` のノード数には確認待ちフォルダのメモが入らないので、数が違って見える場合があります。グラフが空なら、まず保存先が合っているか、メモができているかを確認してください。表示フィルターで除外されている場合もあります。

この使い方に追加プラグインや同期サービスは必須ではありません。すでにあるObsidianの設定を、一式入れ替える必要もありません。

## 9. 次の作業や、別のAIでも同じメモを使う

普段は、AIにこう頼めます。

```text
この作業に関係するPortable Agent Brainのメモがあれば、必要なものだけ読んでください。
作業が終わって、新しくわかった再利用できることがあれば、確認待ちとして保存してください。
```

毎回すべてのメモを読み込ませる必要はありません。単純な誤字修正など、過去の知識が関係しない作業は検索を省けます。

別のAIへ移るときも、既存の保存先を指定して接続します。ソフトを使うAIごとに、別の空のメモ置き場を作り直さないようにしてください。新しいAIから同じ保存先が見えることと、必要なメモを検索できることを確かめます。

別のパソコンや、隔離された実行環境では、同じ名前のパスでも別の場所を指す場合があります。「前のAIには見えていた」だけでは十分ではありません。必要な場合は[実行環境ごとの接続方法](sandbox.md)を確認してください。

## 10. バックアップ・更新・利用停止でメモを失わないようにする

自分のメモの保存フォルダは、大切な文書と同じようにバックアップしてください。Gitを使わないコピーでのバックアップでもかまいません。バックアップ先も公開フォルダにせず、個人情報に合った保存先を選びます。

GitHubへアップロードする操作を `push` といいます。このツールを使うだけなら必要ありません。共有や同期を始める場合は、メモを扱う別の非公開リポジトリを用意し、送信するファイルを確認してください。間違って公開したデータは、あとから公開設定を変えるだけでは取り消せない場合があります。

更新するときは、ソフト本体とメモを分けて考えます。ソフトに自分の変更がないか確認し、新しい版の説明を読んでから更新してください。メモの書式を変える更新なら、先にバックアップします。わからなければ「手元の変更とメモを残したまま更新したい」とAIに相談してください。フォルダを全部消して入れ直す必要はありません。

利用をやめるときは、まずAIの設定からPortable Agent Brainが追加した参照だけを外します。設定ファイル全体を消さないでください。ソフトの場所を移動する場合も、参照先が変わるので接続の確認が必要です。メモは残しておけます。[接続解除の手順](agent-integration.md#rollback)を参照してください。

## 11. エラーが出たら、削除や権限変更の前に確認する

| 起きたこと | 最初に確かめること |
|---|---|
| `python3: command not found`、Pythonが古い | 4章のPythonの確認と導入を行い、ターミナルを開き直す |
| `git: command not found` | Gitが入っているか確認する |
| `already exists` | 同じ場所に既存のソフトがないか確認する。すぐに削除しない |
| `./brain` が見つからない | ソフトのフォルダにいるか確認する。上の手順どおりなら `cd ~/portable-agent-brain` |
| `brain` が見つからない | `./brain` と区別する。5章で説明したソフト内の場所を使う |
| `unknown project` | プロジェクトが未登録か、短い識別名が違う。AIに登録状況を確認してもらう |
| 検索結果が0件 | 保存先、メモの有無、検索語を確認する。最初は0件で正常 |
| Obsidianのグラフが空 | メモの保存フォルダを開いたか、メモとリンクがあるか、フィルターで隠れていないか確認する |
| `Permission denied` | どのファイルにアクセスできないか確認する。むやみに `sudo` や `chmod 777` を使わない |
| AIが設定や履歴を読めない | AIの実行環境とアクセス範囲を確認する。できない操作は、利用者が行う手順を出してもらう |

`pwd` は今いるフォルダ、`ls` はその中のファイルを表示するコマンドです。どこで操作しているかわからなくなったときに使えます。表示に個人名や非公開のファイル名がある場合は、他人に送る前に伏せてください。

実行中の操作を止めたいときは、通常Control＋Cを使います。途中まで作られたファイルが元に戻るとは限らないので、再実行前に何が変更されたか確認してください。

解決しない場合は、使っているOS、実行したコマンド、秘密情報を伏せたエラー文をAIに見せてください。公開の[Issues](https://github.com/nennchakki/portable-agent-brain/issues)に質問する場合も、会話ログ全体、パスワード、APIキーを貼らないでください。

## 12. わからない言葉を引く

| 言葉 | この説明での意味 |
|---|---|
| リポジトリ | ソフトや文書と、その変更履歴をまとめた場所 |
| ターミナル・端末 | 文字を入力してパソコンを操作するアプリ |
| コマンド | ターミナルに渡す操作の指示。AIへの普通の会話文とは別 |
| Markdown・`.md` | 見出しやリンクを書けるテキストの形式 |
| ライブラリ・library | Portable Agent Brainのメモの保存フォルダ |
| 保管庫・vault | Obsidianで開く、ひとまとまりのメモのフォルダ |
| パス・絶対パス | ファイルの場所。絶対パスは、今いるフォルダに左右されない指定 |
| `~`・`$HOME` | 自分用のホームフォルダを表す書き方。実行環境によって場所が違う |
| プロジェクト・slug | ひとまとまりの作業と、それを指定するための短い名前 |
| アダプター・adapter | 各AIに共通のメモの使い方を知らせる指示書。ここでは `external-brain.md` |
| JSON・YAML | 項目名と値を決まった形で書く書式。初回はAIに作成を任せられる |
| candidate・pending | 人が確認する前のメモ、またはその状態 |
| Git・commit・push | Gitは変更履歴を管理する道具。commitは履歴への記録、pushは外部の保存先への送信 |

操作に慣れたら、[コマンド中心の導入手順](getting-started.md)と[メモの書式](knowledge-model.md)も参照してください。最初から全部覚える必要はありません。まずは1つのプロジェクトで、次の作業に持っていきたいメモを残してみてください。
